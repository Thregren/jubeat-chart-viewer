这一版解决「慢网下换歌用不了」和「手机上一屏看不下」两件事，另外把同押光晕改成了双色。
桌面端 / 服务器端的跑法没有变化，前端换掉即可。

## 音源加载进度（慢网）

换歌时整首音源要先下下来、解码成 AudioBuffer 才能精确播放。以前这段等待**界面上没有任何反馈**，
而且卡在 `await` 里：音源没下完，谱面、BPM、物量条全都不显示，点播放也没反应。

- 控制条下面多了一行进度，按阶段显示：`谱面读取` → `音频加载 42%` → `音源解码` → `缓冲中`，
  播放按钮同时转一圈外环。服务器没给 `Content-Length` 时退化成来回跑的动画 + 已下载 MB 数
- **不再阻塞界面**：谱面先渲染出来（时长先按谱面长度算），音源元数据到了再修正
- **加载途中点播放会被接住**：记下这次点击，数据就绪后自动起播。
  以前直接把 `play()` 丢给 `<audio>`，换 `src` 会把它打断而且不报错，表现就是「点了播放没反应」
- 启动时那句「不自动播放就摆成暂停态」不再取消已经排队的播放请求
- 修 `<audio>` 空闲时也会发 `stalled` / `waiting`（它在跟整首下载抢带宽），
  这两个事件把「缓冲中」标志卡住后没人清，导致**播放按钮外框一直转**

## 同押光晕改成双色

- 取色器换成 **6 组预设对比色**：青/洋红、琥珀/蓝、薄荷/珊瑚、柠檬/紫、天蓝/玫红、橙/青绿。
  不给自定义取色 —— 挑两个太接近的颜色等于没区分。下拉框旁边有两个小色块预览
- **同押密集处相邻两批双色交替**（相邻两批间隔 ≤ 0.35 s，约 190 BPM 的一拍），
  一眼能看出哪几个键是一起按的；稀疏的地方只用主色，画面不会太花

## 手机端一屏装得下

按截图反馈砍竖向高度：

- **去掉最底下 `sync` 那一行**（连同快捷键提示；快捷键本身照常可用，见 README）
- **速度 / 偏移 / 循环收进可折叠的选项区**，折叠时完全不占高度
- **物量条高度砍半**：窄屏 92 → 46 px、桌面 72 → 36 px、矮屏 64 → 32 px；
  同步放宽 `layoutDensity()` 里那个 44 px 的兜底，不然会被撑回去
- **物量条在音源未就绪时保留外框**，只把柱子和播放头换成一行提示
  （上一版是整块 `display: none`，会让下面的高度来回跳）

## 曲库列表

- 修**列表能左右拖动**：`.tx` 的隐式 grid 列是 `auto`，而曲名 / 作曲都带 `white-space: nowrap`，
  它们的 min-content 就是整行文字的宽度，把列撑到几百 px（实测 353 px 的列表里内容有 659 px）。
  改成 `grid-template-columns: minmax(0, 1fr)`，长曲名正常走省略号；
  面板再加 `overflow-x: hidden` + `touch-action: pan-y` 兜底

## 其它修复

- 修 `?t=` 深链接在音源就绪前落空（现在会挂起，就绪后自动跳）
- 修 element 后端 seek 没同步 `anchorPos`，解码完成切到 WebAudio 后端时位置跳回 0
  （暂停时拖进度条也会中招）
- 前端资源加了 `?v=` 缓存版本号：nginx 给 js/css 挂了 12h 缓存，不加就会一直吃旧文件

## 部署 / 更新

Release 附件是**不带曲库**的桌面版（每个约 100 MB）：解压直接运行，首次启动用菜单
「文件 → 选择站点目录（site/）」指向自己构建的 `site/`（会记住）。

服务器上更新前端只要传这三个文件，曲库一个字都不用重传：

```
铺面查看器/player/static/index.html   →  <站点根>/index.html
铺面查看器/player/static/app.js       →  <站点根>/static/app.js
铺面查看器/player/static/style.css    →  <站点根>/static/style.css
```

**记得同时改 `index.html` 里的 `?v=` 版本号**，否则浏览器会继续用缓存里的旧 app.js。
