这一版把 marker 从「社区配布的 sprite sheet」整体换成**街机原版逐帧贴图**，渲染时序也不再
靠视频目测，而是从 `jubeat.dll` 反汇编读出来的规格；另外做了一轮代码整理与健壮性加固。
站点体积不变（2.0 GB），前端行为对长押完全没动。

> 说明：上一版 Release 停在 v0.6.8，而线上站点其实已经跑到 v0.6.11（中间几轮只推了站点没发
> Release）。这一版把 v0.6.9 起的全部改动一起补上，所以下面的内容比平时长一些。

## 一、marker 换成官方逐帧贴图

素材来自街机 jubeat（`beyond the ave.`，l44 资源）的 `contents/data/d3/model/*.bin`，
逐帧解出后是 **45 套设计、3974 张 160×160 PNG**（`marker/jubeat_official/`）。每套设计三个通道：

| 通道 | 帧数 | 用途 |
|---|---|---|
| `MA` | 24 | 浮动 / 提示（拍点前淡入） |
| `H1`–`H4` | 4 档 × 16 | 命中爆发，档越高越亮（`H4` = PERFECT） |
| `FR` | 2 | 面板边框，静态装饰（只有部分设计有） |

导入脚本 `tools/import_official_markers.py` 会跳过 `tm0041` / `tm0043` 两套只有替代贴图的联动
marker（提取出来的美术和 Qubell 的替代贴图逐像素相同，放进「官方」列表只会误导人）。

## 二、时序按反汇编规格，不再靠目测

设 `u = 当前音乐时间 − 该 note 的命中时间`（单位是引擎计时单位，1 单位 = 3.3333 ms）：

| 通道 | 帧号 | 有效区间 | 命中瞬间 |
|---|---|---|---|
| `MA` | `floor((u + 155) / 10)` | `u ∈ [-155, +84]` | 第 15 帧 |
| `H` | `floor(u / 10)` | `u ∈ [0, +160)` | 第 0 帧 |

于是 marker 在**拍点前约 0.5 s** 淡入、爆发出现在**拍点上**、约 0.53 s 内收干净。换算收敛在
`manifest.json` 的 `unit_ms` 一个字段里，前端只从那里读，不在代码里再抄一遍常数。

## 三、只在 PERFECT 时播爆发动画

素材不是「一次全播」的：`MA` 走接近动画，`H` 只在命中那一下播对应档位。本查看器是**按谱面
自动全 PERFECT 播放**，所以命中爆发固定取第 4 档；素材缺这一档时回落到该设计可用的最高档。

同时**去掉命中时给 pad 打的高亮**：官方贴图的 `MA` / `H` 通道本身是半透明的，pad 被刷成近白
色之后会从背面透上来，看着就像「marker 被糊了一层」。现在有选 marker 设计时，命中反馈完全交给
marker 自己的动画；选「无（仅面板灯）」时那两条反馈照旧。

## 四、长押

**长押的表现一个字没改**：按下 / 松开各播一次 `H4` 爆发，中间仍然是那个从起点 marker 匀速
移动向终点 marker 的箭头，移动时间 = 倒计时时间。这一版只碰了命中贴图和选项区。

## 五、选项区

- 「按键动画 / 动画对齐帧 / 动画速度 / 命中特效」四个老控件（连同它们的 localStorage 键）
  一起作废，换成一条 **marker（按键动画）** 下拉：45 套官方设计，默认 `#04 快门`，`M` 键轮换
- 新增 **序号颜色** 取色器（默认白色）；拖动时只改内存、松手才写 localStorage，
  `record.js` 的录制预设也钉死成默认值，成片不受录制机历史设置影响

升级时会按前缀清一次老键（`jubeat.markerSpeed` / `jubeat.effect` / `jubeat.anchor.*`），
所以第一次打开会看到新默认值 —— 之后照旧记住你自己的选择。

## 六、代码整理与健壮性

顺手清掉的**真问题**（都不影响页面加载，只在特定路径上炸或静默出错）：

- `window.__player.seState()` 跨层引用了别的 IIFE 的私有变量，**一调用必抛 ReferenceError**；
  改成由 app-audio 自己导出
- 开发服务器 `server.py` 的日志过滤拿格式化模板当路径匹配，等于没生效（`/api/health` 一直刷日志）；
  并且给「文件发到一半出错」补了保护，避免同一条 keep-alive 连接上叠两个响应
- Electron 静态服务的 `createReadStream` 没接 `'error'`，读盘出错会**直接掀掉主进程**（整个应用退出）
- 健康检查与冒烟测试读的是旧字段 `markers`，清单早改成 `designs` —— 于是「45 套素材都在」
  一直被误报成 0
- 曲库索引缓存文件是合法 JSON 但不是对象（被别的程序覆盖过）时，`.get()` 会把请求打成 500；
  现在当「没缓存」处理并重扫
- Electron 的窗口启动与两个菜单回调补了兜底，出错弹提示而不是留一个空白窗口

清理：删掉 4 条没人引用的 CSS 规则、几处只在文件内部用的导出、一个 macOS 复制出来的旧副本
（`markers 2.py`），并修掉一处缩进错乱。界面自测新增一项「契约扫描」——
重新载入后把 `window.__player` 上每个函数真调一遍，专门逮「某层把名字搬走 / 忘导出」这类
只有走到才炸的问题（上一版 `seState` 就是这么漏掉的）。

## 七、升级

站点与轻量包都只是常规替换；带曲库的桌面版整包见文首网盘链接。旧版存下的 marker 相关设置会
在首次启动时清一次，属预期行为。
