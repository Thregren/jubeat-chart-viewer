这一版只做一件事：把长押从「自己发明的扇形倒计时」换成**官方那套「会移动的箭头」**。

0.5.0 起长押的表现是「被按住的格子铺一层蓝色 + 扇形进度 + 居中倒计时」——那是我们按
下落式音游的直觉编的，jubeat 实机没有这个东西。这一版把它整个删掉，改由画布层按谱面时间
现画官方那枚箭头。

## 一、先量，再画

素材是一段 640×480 / 30fps 的 festo 实机录屏（`p1.mp4`，119.833s，3595 帧，
曲目 `jubeat-festo/拙者拙者拙者拙者` EXT Lv10.2，780 notes / 40 holds / BPM195）。
把画面里的 4×4 面板量成「列 x=[97,212,327,442]、行 y=[17,132,247,362]、一格
101px、格距 115px」，再逐帧读格子亮度，得到的东西和直觉不太一样，逐条记录：

| 量到的事实 | 数值 |
|---|---|
| 长押占两格：`index` 是**玩家按住的那一格**（命中动画也画在这里） | `tailTip` 是箭头出发的那一格 |
| 箭头开始前 0.5s 先「起势」 | 走廊光束 + 终点格整格提亮 + 一枚大 V |
| 箭头本体 | 正好一格大的 V（chevron），平边在后、箭尖在前，全程不缩放；实测平边横跨整格宽 101px、箭尖在平边下方 101px |
| 箭头走一条 | 位移严格线性，`进度 = (t − t_note) / (endbeat − t_note)` |
| 平边走完整条走廊 | 345px / 2.4615s = **140.2px/s**（1/2/3 格、上/下/左/右四向都验过） |
| 逐帧直线拟合 | 斜率 **140.27px/s**（理论 140.19），中位残差 0.8px；两端点相隔 2.460s = 长押时长 |
| 时间轴 | 箭头行程就是 `[t_note, endbeat]`（见下面的「时基」） |
| 走过的格子 | 立刻回到空闲外观，不留痕 |
| 跨格缝 | 所有图案都裁在格子圆角里，过缝时自然断开 |

「速度对不对」这件事一开始对不上：按固定偏移叠图比，两边的平边位置会从 +8px 漂到 −7px。
查下来不是时间错，是**两边的「缝」不一样宽**：实机一格 101px 配 14px 缝（缝/格 = 13.9%），
我们面板一格 95.4 CSS px 配 8px 缝（8.4%）。按「格距」归一化之后两边完全一致
（都是 3 个格距 / 2.4615s）。缝的宽度是面板布局的事，这一版不动。

**时基**：直接按固定时间偏移叠图，会被「缝不一样宽」和「录屏整体偏移」两件事同时污染。
改成只跟着箭头自己的两条臂走（把终点格那枚固定 V 排除掉），逐帧拟合出来的结论很干净：
箭头行程的两端落在 `[t_note, endbeat]` 上。另外两条**谱面驱动**（不是输入驱动）的线索
——走廊光束亮起的那一帧、终点格 note 艺术开始出现的那一帧——算出的录屏时基和箭头完全一致
（≈0.10s）。而按下/松开的爆花比谱面只早 ≈0.05s：爆花是**输入驱动**的（玩家手感 / 输入延迟），
比箭头晚 1～2 帧是正常的。所以箭头锚在谱面时间上，别对着爆花挪 `prog`。

## 二、怎么画的

全部在 `app-marker.js` 的一个 draw 通道里现画，坐标用一套「行进坐标系」：
原点 = 起点格后沿中点，`+y` = 行进方向（向上/向下/向左/向右各对应一个整体旋转），
于是 4 个方向共用一份代码。

- **V 的明暗**：亮线只有两条臂和平边；平边中央一块暗楔（顶部宽 ≈0.68 格、深 ≈0.58 格）；
  贴两臂内侧一道浅暗影；V 内侧整体比格底亮一档（≈1.37 倍底色）；箭尖一个亮点正好接上光束
- **描线亮度**：按实机量到的**峰值**取（移动箭头 ≈175、压在亮格上的终点格那枚 ≈167），
  不按倍数放大。我们这边实测 ≈196 / ≈178，比实机高 12% / 6%；再压下去「整行均值」就
  反过来比实机暗了（实机那条线被 640×480 录屏的模糊摊平了：峰值低、行均值高）
- **走廊光束**：很细的亮芯 + 两侧极窄的缓降，半高宽 ≈4px（≈0.04 格），
  峰值就是实机那个淡蓝白 `rgb(195,221,255)`
- **裁切**：每一格都用格子的圆角路径 `clip()` 一次 —— 过缝断开、走过即净
- **不占面板灯**：长押不再往 pad 上加 `hold` 这个 CSS 状态（面板灯只留「命中闪灯」和
  「落点前微亮」两种），箭头是画布上的东西

## 三、同时补上「按下 / 松开各一次命中动画」

量箭头的副产品：一个长押在 `t_note` 和 `endbeat` **各播一次同一套 marker 命中动画**，
两次都画在 `index` 那一格上（`tailTip` 那格全程不闪）。以前 `drawMarkers()` 里
`else if (seg.holdEnd != null) continue;` 把长押整段跳过了，所以长押永远不会命中，
`drawMarkers()` 现在按 `holdDur` 把时间轴折回去，让末拍再播一遍。
`HOLD_POST` 也跟着从 0.35 收到 0.28（终点格的 V 到 `endbeat` 就该让位给爆花）。

## 四、顺手修掉一个「换谱面就白屏」

`app-library.js` 里还留着 `state.holdUntil.fill(-1)` / `state.holdFrom.fill(-1)` 两行，
但这两个字段在 `app-base.js` 里已经删了 —— 点任何一首新歌都会
`TypeError: Cannot read properties of undefined (reading 'fill')`。
`tools/ui_smoke.js` 换曲目那条路径正好覆盖到，修前 8/40 失败，修后 45/45。
