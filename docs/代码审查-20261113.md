## 2. 安全

### 2.1 P0

**#1 安卓签名口令硬编码回退** — `android/build.sh:43-51`

```sh
elif [ -f "$KS" ]; then
  # 兼容早期脚本生成的本地密钥。
  KS_PASS=jubeatviewer
```
有 keystore 但缺 `.password` 时，口令退化成源码里的字面量。keystore 虽已 gitignore，但一旦随备份/误提交外泄，口令这道防线等于不存在。
**改法**：删掉回退分支，缺口令直接报错退出；口令只从环境变量或 0600 文件读。**收益**：密钥库泄露后仍有第二道防线。

**#2 nginx 示例缺「点文件」拦截** — `deploy/nginx-site.conf.example`

示例里只有 `location ~ ^/\.well-known/`（61 行），没有 `.` 开头路径的拒绝规则，而构建会往站点根写 `.build-sources.json`（`site_builder.py:567`）和 `.asset-history.json`（`site_gc.py:17`）；`deploy/README.md` 的部署命令是 `rsync -av`，会连点文件一起同步。
**已核实**：线上实际 vhost 里有 `location ~ /\.(?!well-known/) { return 404; }`（第 60 行），公网请求这两个文件是 404；**但照抄示例新建环境就会泄露**——拿到全曲 SHA256 签名、转码 profile 与全部已发布文件清单。
**改法**：把线上那条 `location` 补进示例（放在所有正则 location 之前），并把这两个文件加进 `tools/check_deployment.py` 的探测清单。**收益**：堵掉一条零前置条件的信息泄露，顺带覆盖 `.git`/`.env`/`*.swp`。

**#3 `write_atomic` 产物 0600** — `player/media.py:198-211`

`mkstemp` 固定建 0600 且没有 `chmod`，`os.replace` 会把 mode 一起带过去。走这条路的是 `static/*.js|css`、`data/library.json`、marker 图集、入口页（`build_directory.py:58`、`web_assets.py:88,145`）。`rsync -a` 保留权限 → 线上 root:root 0600 → nginx 以 www 运行即 403。
**旁证**：`deploy/README.md:79-81` 专门对音频目录交代 chown/chmod 644，说明这个坑踩过。
**改法**：`os.fchmod(fd, 0o644)` 或保留原文件 mode；顺带与 #23 合并成一份实现。**收益**：不再出现「文件在但 403」。

**#4 脏值 `.trim()` 白屏** — `static/app-wiring.js:329`

```js
if (saved[key] == null || saved[key].trim() === '' || ...
```
`saved` 来自 `SettingsStore`（`services.js:24-51`），会先读 Electron/Android 原生桥。桥里返回数字/布尔时 `.trim` 抛 TypeError，`app.js:138-147` 的 catch 会把整页替换成一行启动失败文本。这是唯一一处把外部存储值当字符串直接用的地方。
**改法**：`const raw = saved[key] == null ? '' : String(saved[key]).trim()`。**收益**：消除「壳里打开就白屏且报错与真实原因无关」。

### 2.2 P1

**#5 访客接口 Origin 可伪造** — `deploy/visitors/endpoint.php:23`

```php
$expected=getenv('VISITOR_STATS_ORIGIN')?:'https://'.($_SERVER['SERVER_NAME']??'');
```
`SERVER_NAME` 在 `UseCanonicalName Off` 时来自请求 Host。直接打源站 `Host: evil.example` + `Origin: https://evil.example` 即通过 CSRF 检查，`counters` 与 `popular_songs` 可被任意刷高，而热门榜会被 `app-visitors.js` 渲染成「7 日热门」。
**改法**：`VISITOR_STATS_ORIGIN` 改为必填，缺失即拒绝；nginx 固定 `server_name` 并拒绝其它 Host。**收益**：站内唯一外部数据位不再可被第三方操控。

**#16 三端本地服务都没有 CSP** — `electron/site-server.js:77`、`LocalServer.java:270`、`player/server.py:91`

只有 `X-Content-Type-Options`/`Referrer-Policy`/`X-Frame-Options` 三条；线上 `deploy/security-headers.conf:13` 有严格 CSP。客户端恰恰是「用户自带内容」（导入 ZIP、USB 拷入目录）的场景，缺这层就没有兜底。
**改法**：三端补同一串 CSP（`default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'none'`），并用 `tools/test_cache_headers.py` 那套静态断言把四端口径钉住。**收益**：注入面多一层纵深防御。

**#17 明文全局放开** — `android/app/AndroidManifest.xml:20`

`usesCleartextTraffic="true"` 是应用级开关，实际只需要 `http://127.0.0.1:<port>`。
**改法**：改 `network_security_config.xml`，`base-config cleartextTrafficPermitted="false"` + 只给 `127.0.0.1`/`localhost` 开。**收益**：明文只对回环开放，其他域名被系统拦死。

**#18 本地服务无调用方鉴权** — `LocalServer.java:181`

只校验 `Host: 127.0.0.1:<port>`（防 DNS rebinding），不校验调用方。同机任意进程扫到随机端口后带同样 Host 即可 GET 全部 `data/media/markers`——曲库是受版权保护的音源与封面。
**改法**：启动时生成一次性 token 拼进 URL 或设 HttpOnly Cookie，除 `index.html` 外都要求匹配。**收益**：从「同机任意进程可读」收敛到「只有 WebView 可读」。

**#19 CI 供应链** — `.github/workflows/ci.yml:36-76`

`actions/checkout@v4`、`setup-node@v4`、`setup-python@v5` 都是可被上游重打的 tag；`pip install pillow` 无版本无哈希。这两个 job 会跑 `check.sh --release` 与打包/浏览器回归，被投毒即可改写上传的产物。
**改法**：action 固定到 commit SHA 并注释版本；pillow 用 `requirements.txt` + `--require-hashes`；加 dependabot 管 `github-actions` 与 npm。**收益**：「CI 被上游影响」从不可见变可审计。

### 2.3 P3

**#37 开发服务器 `?reindex=1`** — `player/server.py:228`
任何 GET 加 query 即触发 `LIB.load(force=True)` 全量重扫，48 个连接槽期间会被占满。默认只绑 `127.0.0.1`，**线上不跑**，所以不是公网 DoS；但本机开着 ngrok/反代给别人看时会中招。
**改法**：`JUBEAT_ALLOW_REINDEX=1` 才生效，或加一次性 token；加「距上次 load 不足 N 秒忽略」节流。**收益**：开发机安全卫生。

## 3. 冗余与可合并

### 3.1 结构性重复（P2）

**#21 四端「发文件」各写一遍** — `electron/site-server.js`、`LocalServer.java`、`player/media.py`、`deploy/php`

同一套语义（Range、206 头、缓存头、错误响应）四份实现，且已经漂移：
- MIME 表：桌面有 `.caf: audio/x-caf`、`.webm`，安卓有 `.txt` 但**没有** `.caf/.webm`，同一个文件在两端 Content-Type 不同（C11）。
- 错误响应：`site-server.js:157,169,173` 的 400/403/404 不带 `BASE_HEADERS`，只有 180 行的 404 带；安卓三处都带（C12）。
- 契约测试只覆盖纯函数（`parse_range`/`resolveSafe`），HEAD 语义、206 的 `Content-Range`、错误头都没有对拍。

**改法**：① MIME 抽成 `assets/mime.json` 三端共用；② 定义「请求 → 状态码 + 关键响应头」golden 表，扩 `tools/test_range.py` 跑四端；③ 统一错误响应公共头。**收益**：改一处漏三处的风险显性化。

**#22 哈希文件名判定 5 份 / `stem_of` 5 份** — `site_gc.py:20`、`site_builder.py:383`、`package_site.py:12-15,91`、`verify_site.py:295`、`web_assets.py:72`；`stem_of`：`site_builder.py:62`、`verify_site.py:76`、`package_site.py:62`、`build_share_pages.py:91`、`library.py:81`

这些谓词决定「哪些文件可被 GC/打包」。漏改一处就是误删线上资源或漏打包。
**改法**：在 `tools/asset_hash.py`（已存在）里加 `HASHED_RE`、`is_hashed()`、`strip_hash()`、`stem_of()`，全仓 import。**收益**：判定口径从 6 处收敛到 1 处。

**#23 原子写 4 份实现，权限语义各不相同** — `media.py:198`、`build_share_pages.py:41`（`chmod 0o644`）、`finalize_frontend.py:18`（保留原 mode）、`compress_directory.py:35`（只有 fsync）

这正是 #3 的根因。
**改法**：合并为 `media.write_atomic(path, data, mode=...)` 一份，其余调用点删掉本地实现。

**#24 前端 `notes` 二分 3 份** — `app-marker.js:521-527`（`notesInWindow`）、`app-density.js:347-353`（`bucketInfo`）、`app-audio.js:350-357`（`sfxReset`）

**改法**：统一改调 `Core.firstAfter`，容差作为参数传入（`sfxReset` 传 `now - 1e-4`）。**收益**：少 30 行重复，判定口径只有一处。

**#25 播放图标/aria 6 处手写** — `app-player.js:902,945,972`、`app-library.js:649`、`app-wiring.js:549,554`

`setPlaying()`（`app-audio.js:391-398`）的注释写明「`state.playing` 的唯一写入口」，但图标同步没一起收进去，而 `<audio>` 的 `playing/pause` 事件还会再同步一次，存在竞争。

**#26 启动参数解析 9 次** — `app-render.js:19,21,24` 连续三次，另有 `app-player.js:32,37`、`app-marker.js:1040`、`app-wiring.js:36,171`、`record.js:17`

### 3.3 两条构建流水线
这里要更正一个容易误判的点：`compress_directory.py` **不是** legacy MCZ 链路，它读的是目录曲库（`load_directory`），职责是「WAV 母库 → Opus 精简库」，用于产出网页/客户端用的压缩曲库（`docs/压缩曲库与客户端.md:27`）。所以它和 `build_directory.py` 是**同级的两条流水线**：一条转码后发布，一条原样直发。

问题是两条的发布尾完全重复 —— `compress_directory.py:133-141` 与 `build_directory.py:69-82` 逐行对应（`publish_catalog` → `optimize_markers` → `hash_frontend` → `build_share_pages` → `build.json`）。另外 `compress_directory.py:20` 的 `PROFILE` 常量与第 73 行整条 ffmpeg 命令行，是 `audio_opus.py:160-167` 参数的硬编码副本：改码率要手工同步两处，而且 `PROFILE` 字符串格式与 `audio_opus.profile()`（带 ffmpeg 版本）不同，缓存键会漂移。
**改法**：抽出 `publish_site(out, songs, version)` 供两条共用；ffmpeg 参数改为调用 `audio_opus` 的实现，删掉本地 `PROFILE`。

## 4. 性能

### 4.1 构建期（P1，每次构建都在付）

**#8 `copy_or_link` 全量读文件比较** — `tools/build_directory.py:25-31`

上一行注释写着「避免把几十 MB 音频读成两份内存做比较」，下一行就是 `source.read_bytes() == dest.read_bytes()`。mtime 一变（重新拷库、rsync、时钟变化）就对每首歌各读两份。同类写法：`site_builder.py:247`（把已编码的音频再读一遍比）、`verify_site.py:158`（为看 JPEG 头 2 字节读完整张缩略图，4000 次）。
**改法**：复用 `package_site.py:32-39` 已有的 `equal_streams()` 流式比较；取头字节改 `f.read(2)`。**收益**：消除 2G 内存机的构建内存尖峰，少读一遍盘。

**#9 `asset_path` 每次两次 `resolve()`** — `player/directory_library.py:17-20`

`root.resolve()` 在 `load_directory:34` 已经做过，但 `asset_path` 每次再对 root 和目标各 resolve 一次（逐级 lstat）。4000 首 × 约 10 次调用 ≈ 4 万次 resolve；`build_directory.py:44-46` 又对全部 assets 再跑一遍 `asset_path(...).is_file()`，同一批检查做两次。
**改法**：loader 内传已 resolve 的 root；用「拒绝 `..`/绝对路径后直接 join」替代逐次 resolve；构建侧删掉重复的第二轮检查。**收益**：单次索引加载少 3–4 万次 syscall。

**#10 发布事务的全树遍历** — `tools/site_transaction.py:45-76`

`copytree(..., copy_function=os.link)` 给上万个文件建链接，`publish` 里再各来一遍 `rglob` 并逐文件 `os.path.samefile`；`site_builder.py:382`（`retain_hashes`）、`186`（`prune`）、`site_gc.py:35,67` 还有 4 遍。站点约 2 万文件，等于每构建十万级 syscall，且这些集合高度重合。
**改法**：构建直接产出「本次引用集合 + 上次清单」，一次遍历完成 diff 并喂给 prune/transaction；stage 改为按需 copy-on-write。**收益**：构建尾部从分钟级 stat 洪水降到一遍扫描。

**#11 `publish_catalog` 写两遍** — `tools/web_assets.py:79-83`

`write_changed(canonical, content)` 后又 `write_changed(alias, content)`，同一份内容（可能数百 KB 到 MB）写两遍、哈希算两遍，而 `write_changed` 内部还有一次 `read_bytes()` 全量比较。
**改法**：先写 canonical 再 `os.link` 出 alias；`write_changed` 先比 size。**收益**：少写一半字节。

### 4.2 客户端（P1）

**#12 安卓启动主线程重写前端** — `MainActivity.java:67-71,367-375`
`stageFrontend()` 把 `www/static/` 全量覆盖（8.6MB，其中 `background-stories-data.js` 6.8MB），没有 size/mtime/版本比对（桌面端 `main.js:24-32` 的 `copyIfChanged` 有）；`onCreate`、导入完成、权限回调都会跑。且 `aapt2 link` 未加 `noCompress`，`am.open` 要在主线程解压再写盘。
**改法**：挪后台线程 + 版本标记（VERSION/清单 hash 写 SharedPreferences）或 size+mtime 比对，仅版本变化时覆盖。**收益**：消除首帧前数百毫秒阻塞与低端机 ANR 风险，减少闪存写放大。

**#13 安卓请求头逐字节读** — `LocalServer.java:223-239`
`while ((b = in.read()) != -1)` 无 `BufferedInputStream`，一屏几十个请求 × 每个 400–800 字节 = 上万次 syscall；超 64KB 直接 `return null`，不回 431。
**改法**：`BufferedInputStream(socket.getInputStream(), 8192)` 或按块找 `\r\n\r\n`；超限回 431。**收益**：syscall 降两个数量级。

**#14 Electron 偏好同步 IPC** — `electron/preload.js:9-18`
`getItem/setItem/removeItem` 全走 `sendSync`，前端 `STORAGE` 有 29 个键，启动即 29 次阻塞往返；写入时 `preferences.js:29-35` 每个键把整个 JSON 重写一次。
**改法**：加 `getAll()/setMany()` 合并成一次 IPC + 一次落盘。**收益**：启动阻塞往返 29 → 1。

**#15 Electron 首帧前同步 I/O** — `electron/main.js:19-38,82-94`
`resolveSiteDir()` 对最多 4 个候选目录各 `readFileSync` + `JSON.parse`（数百 KB 到 8MB），随后 `stageFrontend()` 逐文件 stat、必要时 `copyFileSync` 8.6MB，全在 `createWindow()` 里、`loadURL` 之前。
**改法**：探测与暂存挪到 `app.whenReady` 之后异步；先用构建期生成的小索引判断 format。**收益**：冷启动首帧立即出现。

### 4.3 访客统计（P1）

**#6 每次点歌事件全量解析主索引** — `deploy/visitors/visitor-catalog.php:14`
```php
$first=catalog_identity($catalog);$data=catalog_json($catalog);
```
命中缓存也要 stat + 读 + `json_decode` 整棵（上限 8MB，线上 300KB+），只为算 signature；版本索引反而在 `if ($current!==$signature)` 内才解析。
**改法**：先比 `(ino,size,mtime,ctime)` 组出的 signature，相同直接查 `catalog` 表。**收益**：热路径从「读+解析 8MB JSON」降到「一次 stat + 一次索引查询」。

**#7 事件写入同步 fsync + 每请求聚合** — `deploy/visitors/endpoint.php:66,105-107`
一次 POST 两个写事务，提交后同步 `visitor_export()`（最多 4 批 × 50 行，每批 fopen+flock+fwrite+fflush+fsync），再无条件跑 `visitor_popular()`（7 天 `GROUP BY`）与 `visitor_today()`；GET 同样跑且无限流。
**改法**：export 移到 `maintenance.php --flush` + cron；popular/today 写 meta 表做 30–60s 缓存。**收益**：POST 延迟与磁盘 fsync 解耦，降低写锁争用与 503。

### 8.3 访客统计的回归（部署前复查出，已修）

§8.1 里 #5/#6/#7 是照仓库里的 PHP 改的，但仓库那份比线上副本旧，直接部署会退功能：

- **`chart_loads` / `today_chart_loads` 被整段删掉**。线上 endpoint 与 storage 早已有 v5 迁移、`visitor_chart_loads()` 与「非 bot 且首次插入才 +1」的计数，`app-visitors.js` 与「关于」面板正是读这两个字段。重写版把它们当死代码删了，部署后「历史/今日谱面加载」会变成 `—`。已按线上语义补回（迁移 + 函数 + `visitor_public_stats()` 展开），并把它们固定进 `test_visitors_http.py`。
