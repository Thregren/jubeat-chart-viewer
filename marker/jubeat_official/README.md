# jubeat 官方 marker 逐帧贴图（`jubeat_official/`）

街机 jubeat（`beyond the ave.`，l44 资源）里的**官方 marker 贴图**，从
`contents/data/d3/model/*.bin`（PXET → PMAN → orglz → TDXT）里逐帧解出来，
一共 **45 套设计**、每套 88–92 张 160×160 PNG。

**没有收录的两套**：`tm0041`（干物妹！小埋）与 `tm0043`（AC 版迪士尼 松松）。
这两个联动 marker 的美术没随版本进包 —— 提取出来的是 Qubell 的替代贴图，两套的
88 帧逐像素完全相同（提取项目 `MARKER_NAMES.md` 标为「⚠️ 替代贴图」）。
放在「官方 marker」列表里只会误导人，因此导入脚本直接跳过（`tools/import_official_markers.py`，
判据是 `marker_names.json` 的 `art_status != ok`）。

渲染时序不是照着视频抄的，而是从 `jubeat.dll`（i386）反汇编读出来的
——见下面的「时间模型」。查看器（`铺面查看器/player/static/app-marker.js`）
就是按这张表画的。

## 目录结构

```
manifest.json              机器可读清单（下面「清单字段」一节）
tex_l44_tm0001/           一套设计一个目录
  TM0001_MA00.png … MA23  浮动 / 提示（24 帧）
  TM0001_H100.png … H115  命中爆发第 1 档（16 帧）
  TM0001_H200.png … H215  第 2 档
  TM0001_H300.png … H315  第 3 档
  TM0001_H400.png … H415  第 4 档 = PERFECT
  TM0001_FR00.png … FR01  面板边框（静态装饰，只有部分设计有）
```

命名规则固定为 `<目录>/<前缀>_<通道><两位帧号>.png`；这条约定在
`铺面查看器/player/markers.py` 的 `frame_rel()` 里只有一份实现，
构建脚本 / 校验脚本 / 前端三方共用。

不是每个设计都满帧（少数设计会多出 `MA24` / `H416` 这类美术附加帧），
引擎公式只到 24 / 16，清单按 24 / 16 记，多出来的帧按设计忽略。

## 时间模型（从 `jubeat.dll` 反汇编，已验证）

一个 marker 分三个通道。设

```
u = 当前音乐时间 - 该 note 的命中时间      （单位 = 谱面计时单位，1 帧 = 10 单位）
```

| 通道 | 帧数 | 帧号公式 | 有效区间 | 命中瞬间 |
|---|---|---|---|---|
| `MA` 浮动 / 提示 | 24 | `floor((u + 155) / 10)` | `u ∈ [-155, +84]` | **第 15 帧** |
| `H` 命中爆发 | 4 档 × 16 | `floor(u / 10)` | `u ∈ [0, +160)` | **第 0 帧** |
| `FR` 面板边框 | 2 | 静态 | 不随时间变化 | —— |

状态机（`jubeat.dll` @ `0x101a25b0`）：`state == 0` 画 `MA`；`state == 1` 不画；
`state == 2…5` 分别画 `H1…H4`，档位基址 `base = (state - 2) * 16`。
**jubeat 没有单独的「过早 / 过晚」贴图**：提前按只是看到 `MA` 的靠前帧，
屏幕上那个 `+/-ms` 数字属于 UI 贴图，不在 marker 素材里。

### 判定档 ↔ 贴图

4 个档的美术顺序是实测出来的（档位越高越亮、越花），判定名是**推断**：

| 档 | 贴图 | 实测亮度峰值 | tm0001 / tm0020 造型 | 判定 |
|---|---|---|---|---|
| 1 | `H1xx` | 0.114 | 红 / 墨 | POOR |
| 2 | `H2xx` | 0.396 | 青 / 线描花 | GOOD |
| 3 | `H3xx` | 0.505 | 金 / 上色花 | GREAT |
| 4 | `H4xx` | 0.923 | 彩虹 / 全彩「華」 | **PERFECT** |

本查看器是「按谱面自动全 PERFECT 播放」，所以命中爆发固定取**第 4 档**；
素材里缺这一档时前端回落到该设计可用的最高档，不会整格开天窗。

### 单位 → 毫秒

`jubeat.dll` 里没有「单位→毫秒」的常量，只有「每帧 = 10 单位」。所以换算是
**拿实机画面逐帧量出来的**：用 640×480 / 30.000 fps 的实机录像做贴图模板匹配，
MA 的每一帧恰好对上录像的每一帧（MA01→第 1493 帧、MA02→1494……连续 1:1），
命中爆发首帧（MA 第 15 帧）正好落在 14 帧之后。也就是：

    1 动画帧 = 1 视频帧 = 1/30 s ≈ 33.333 ms  →  1 单位 = 3.3333 ms

这个换算收敛在 `manifest.json` 的 `unit_ms` 字段：前端只从那里读，将来有反证改一处即可。

按这个换算：每帧 33.333 ms、`MA` 提前量 516.7 ms、`H` 爆发全长 533.3 ms。
`MA` 第 15 帧（命中瞬间）正好在**拍点前 0.5 s**（15 帧 × 33.333 ms），
实机录像里 MA01 到命中点相距 14 帧 = 466.7 ms，与模板匹配逐帧吻合。

## 清单字段（`manifest.json`）

| 字段 | 内容 |
|---|---|
| `unit_ms` / `units_per_frame` | 3.3333 / 10（见上节） |
| `hit_window_units` | `{early: -155, late: 160}` |
| `ma` / `h` / `fr` | 各通道的帧数、命中帧、结束位置 |
| `judge_tiers` | `{POOR: 1, GOOD: 2, GREAT: 3, PERFECT: 4}` |
| `designs[]` | 45 套：`id` / `num` / `dir` / `prefix` / 日英中文名 / 出现版本 / `ma` / `h` / `fr` |

`markers.py` 读取时会再做一遍白名单裁剪（目录必须以 `tex_l44_tm` 开头、
前缀必须以 `TM` 开头、挡掉带斜杠的值），坏 json 返回空清单而不是 500。

## 重新导入

素材包（含 `out/markers/` 与 `ANIMATION.md`）不在仓库里，拿到之后：

```sh
python3 tools/import_official_markers.py --src "/path/到/jubeat marker提取"

# 只想收 PERFECT 一档（省 39 MB 永远画不到的贴图）：
python3 tools/import_official_markers.py --src "…" --tiers 4
```

默认收 `MA` + `H1…H4` + `FR` 三条通道共 3974 张 / 77 MB（45 套设计）；
跳过了 `tm0041` / `tm0043` 两套只有替代贴图的联动 marker。不复制 mini 版
（`*_m`，40×40）、`_sheets/`、`_src/` 和商店图标 —— 前端用不上。
