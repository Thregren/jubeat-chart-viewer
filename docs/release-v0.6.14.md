# v0.6.14 · 官方曲库补全 + 长押尾判计入连击

这一版把曲库和官方对齐（**1371 → 1479 首**），并修掉长押计数、面板蓝光、同押高亮三处
手感和观感问题。线上站点 <https://ub.thregren.world> 已经同步到这一版。

## 一、曲库补全：1371 → 1479 首

对着本地全套游戏解包逐首比对之后，做了三件事：

| 项 | 之前 | 现在 |
|---|---|---|
| 曲目 | 1371 | **1479** |
| 谱面 | 4103 | **4427** |
| 封面 | 1324 | **1422** |

1. **曲库里有、但缺封面的**：从官方素材里把封面调回来，同时修掉源包里几张**本身就是坏的
   PNG**（HEKIREKI、こどなの階段、となりのトトロ feat_sayurina、マスターピース、女々しくて
   等），列表里不再退化成 ♪ 占位。封面完整性现在是「1422 / 1479」。
2. **官方有、而曲库没有的**：谱面、音源、封面一起导入，URL 布局和原来的曲目完全一致。
3. **48 首老版权曲恢复索引**：它们的谱面成员名是 `曲名_难度.mc`（不含 `Lv<等级>`），旧规则
   认不出，整首被丢出索引。现在改用 `_BSC/_ADV/_EXT` 兜底解析，等级取自 atwiki 全曲表并
   交叉验证（`tools/official_levels.json`）。1479 首里**没有任何一个难度缺等级**。

新增两个维护脚本：`tools/official_import.py`（官方曲目导入）、`tools/fix_covers.py`（裂图
修复），官方曲目清单在 `tools/official_songs.json`。

## 二、长押尾判算一颗 note

以前一颗长押只算一颗 note，**尾判不计入连击也不计入总数**，曲末永远差几颗连不满。
现在口径是 `tap + hold × 2`：

- `core.parseNotes` 额外出 `holdEnds[]`，`nTotal = tap + hold × 2`；
- 播放推进到某颗长押的尾判时，补一次 `bumpCombo` + 光晕脉冲，和普通 note 一样；
- 物量条的「已过 / 总数」跟着新口径走。

例：`festo / 1116` BSC 是 452 tap + 36 hold，旧口径 488，新口径 **524**，曲末能连满 524/524。

## 三、面板周围那圈蓝光去掉了

蓝光来自 `.pad.hit` 的第三层 `box-shadow`（48px 蓝色），面板不在 `overflow` 容器里，四角
格子会透到面板外。删掉该层之后只剩白色 1px 描边 + 24px 光晕，面板外圈干净了。

## 四、同押高亮：可换样式，跟着序号走

- 新增「**同押高亮样式**」：`光晕 / 加粗面板框 / 两者`，默认光晕。序号和高亮解耦，
  只开高亮不显示数字也能看。
- 序号切到右下角时，光晕的圆心和半径**跟着数字走**（并夹回格内避免裁边），不再永远占满
  整格。
- 原有的透明度滑杆（默认 **70%**）和「暂停后不呼吸」对两种样式都生效。

设置版本 `settingsVersion 6 → 7`，旧设置自动沿用。

## 五、已知限制

- **57 首在现有官方素材里确实找不到封面**（例如 A Dance & A Beer、Are U Ready?、
  BRANDNEW DAYS），列表退化成 ♪ 占位；要补齐得等新的素材来源。

  Chrome / Edge / Firefox）。
