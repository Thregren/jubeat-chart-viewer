# OFT 回放匹配优化

优化现有谱面查看器的导入链路。回放文件仅在浏览器读取。所有自动匹配仍须通过同格、同顺序、逐 note 最大 4 ms 的现有校验。音频、封面和物量资源与候选谱面 JSON 分开计量。

## 实施顺序

1. **复用命中谱面。** 把已验证的 payload 随候选传给原有的选曲入口，按曲目与难度绑定，仅在这次加载中消费，继续使用播放器现有的有界缓存。未命中谱面不写入播放器缓存。谱面被用户手动切换，或导入关闭、重开时，旧任务不能挂载回放。
2. **新版精简回放。** 导出 JBR2，保留原 note、分数与连击数据，再加曲库 ID 和难度代号。兼容读取压缩及未压缩 JBR1/JBR2。JBR2 用当前曲库精确查找候选，通过原有逐 note 校验后打开。提示缺失、失效、谱面不可读或校验不符时回到完整候选搜索。同一次导入优先候选成功读取后无需再下载，暂时读取失败的候选可在完整搜索中重试。无提示文件仍逐一验证所有候选，以保留多匹配选择。
3. **评估候选索引。** 用本地曲库模拟 16 格 note 数量过滤，量化候选和压缩流量，并找拥挤档位。若要再试首个落点，比较时需保留 4 ms 容差。新增索引须与曲库同版本更新，仅在导入需要时读取，且错误或缺失时仍能走原匹配。只有计入索引自身后冷导入谱面匹配流量下降至少 30%、限速下匹配时间改善且完整匹配集合一致，才考虑上线索引。

## 验收

| 场景 | 边界 |
| --- | --- |
| WONDER WALKER EXT 原始 OFT、OFT.GZ、JBR1 | 曲库冷缓存下候选谱面从 3 次读取降至 2 次，命中后不重复取谱 |
| 同一局导出 JBR2 后冷导入 | 1 次谱面读取，gzip 文件小于 20 KiB，解码后每颗 note、偏差、判定及分数连击时间线完全一致 |
| 失效或错误的 JBR2 提示 | 恢复完整搜索。有效但时间不符的候选不重复下载。多匹配仍可选择，无匹配明确提示 |
| 关闭、重开、快速切歌及候选读取失败 | 旧导入不能挂载回放。手动选曲和缓存仍正常。读取失败不能误报成无匹配 |
| 现有回看 | 同一 16 格布局，偏差正红负绿，物量按判定着色，播放和向前向后拖动后的分数连击均与原记录一致 |
| 文件隐私 | 请求中无回放内容、文件名或判定记录。旧示例不恢复，无回放文件进入发布物 |
| 测量 | 区分冷缓存和暖缓存。分别记录候选请求次数、编码字节、曲库准备和匹配耗时。用相同曲库、文件和网络条件比较，至少报告拥挤档位和真实样本 |

实现和验证在现有网页版源码及本地预览完成。生产部署和 release 作为独立发布步骤。

## 执行记录

### 复用与精简回放

- 命中谱面通过已有选曲和缓存链路打开。未命中候选不写入播放器缓存。导入记录选曲请求的身份，用户切歌后旧结果无法覆盖当前谱面。
- JBR2 的 JSON 布局为 `[notes, progress, maxCombo, [songId, chartCode]]`，前缀由 `JBR1\n` 变为 `JBR2\n`。原数组的编码精度保持不变，时间以 10/3 ms 为单位，偏差精确到 1/3 ms。OFT 与精简文件按此精度比对，JBR1 与 JBR2 的前三组解码数据逐项相等。
- WONDER WALKER EXT 的 JBR2 gzip 为 **13,981 字节**，总分 **871,298**。浏览器验证了 893 条偏差记录、面板颜色、物量列颜色、播放及拖动后的分数和连击，同时覆盖错误文件、多个匹配和无匹配。旧入口仍只打开空的导入窗口。

在同一站点资源上对比原版和本地替换了前端资源的新版，Edge 禁用 HTTP 缓存，曲库预先加载，模拟 80 ms 延迟和 1.5 Mbit/s 下载。冷 OFT 与 JBR2 各跑三次，表中耗时为中位数，从首个谱面请求发起到最后一个谱面请求结束。传输字节使用浏览器 Resource Timing 统计，仅计谱面 JSON。

| 导入 | 谱面请求 | 压缩响应体 | 浏览器传输计量 | 匹配请求窗口 |
| --- | ---: | ---: | ---: | ---: |
| 原版 OFT，冷缓存 | 3 | 9,961 B | 10,861 B | 296 ms |
| 新版 OFT，冷缓存 | 2 | 6,708 B | 7,308 B | 140 ms |
| 新版 JBR1，冷缓存 | 2 | 6,708 B | 7,308 B | 136 ms（单次） |
| 新版 JBR1，同页再导入 | 1 | 3,455 B | 3,755 B | 355 ms（单次） |
| 新版 JBR2，冷缓存 | 1 | 3,253 B | 3,553 B | 147 ms |

JBR2 在这局比新版 OFT 少一次谱面请求。两份 OFT 候选本可并行，三次样本的中位数没有显示 JBR2 进一步缩短请求窗口。原始 OFT 从选择文件到对话框关闭的中位数由 829 ms 降到 250 ms，同条件 JBR2 为 234 ms。

JBR2 曲库 ID 失效时回到两次候选读取。ID 有效但落点不匹配时也共两次读取，已验证不匹配的谱面只读一次。首次请求返回 503 时会重试这张谱并核对另一张。普通 OFT 的候选读取失败会显示读取错误。故意延迟候选读取后切换难度，或关闭窗口再导入损坏文件，旧任务均未挂载回放。仓库 `sh tools/check.sh` 通过，含 246 个前端、平台与录制单测。

### 16 格索引试验

本地曲库修订 `3fafcf6342e86eaf237b`，纳入 6,385 张符合现有入口条件的谱面，分成 901 个 note 数档位。逐张谱面生成量化至 OFT 时钟的回放，按原规则执行 65,187 次候选比较。增加 16 格计数过滤后，所有 6,385 份回放的完整匹配集合一致。计数相同的候选仍要逐 note 比对。175 档的测试样本有 10 个完全匹配版本，应继续交由用户选择。

冷缓存按档位取 gzip 分片，计入分片本身和剩余候选谱面。Edge 本地 HTTP，80 ms 延迟、1.5 Mbit/s 下载，三路并发，每组交错跑五次，记录匹配耗时中位数。流量为压缩响应体，不含头部、音频、曲库初始化。

| 档位 | 请求数（含分片） | 压缩响应体 | 匹配耗时 |
| --- | ---: | ---: | ---: |
| 175 note，最多计数碰撞的样本 | 59 → 11 | 53,723 → 9,772 B | 1,783 → 441 ms |
| 430 note | 29 → 2 | 49,597 → 2,571 B | 1,001 → 185 ms |
| WONDER WALKER EXT 同谱量化样本，893 note | 2 → 2 | 6,723 → 3,464 B | 128 → 194 ms |

若每张谱面等权，按档位分片的估算冷匹配响应体平均为 2,294 B，原搜索为 16,844 B。全库一次下载的索引本身为 126,078 B。估算使用本地曲库的 gzip 文件大小与合成回放，线上曲库档位数和真实导入分布可能不同。

本轮停在索引试验。全量启用会拖慢双候选档位。若单独推进拥挤档位，先按同版本分片做灰度，用正式曲库和真实流量分布确定候选数门槛，再验证分片缺失、过期、缺行和读取失败的回退，保留逐 note 校验和多版本选择。首个落点在 175 档仍有大量碰撞，本轮保留单纯的格子计数试验。
