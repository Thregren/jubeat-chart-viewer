这一版把「播放正确性」彻底重做了一遍，另外补齐了手感细节（打点音、同押光晕）。

## 播放：换成 WebAudio 直出，不再有 seek 后的错位

之前拖动进度条 / 按 `←`/`→` 跳转之后，音乐会和 marker + 打点音整体错开（音乐还会跑快）。
排查结论：解码音频与 `currentTime` 完全同步、跳转落点 0ms 误差，问题出在**输出路径**——
`<audio>` 直出和 WebAudio 打点音是两条输出，而 seek 会重建媒体管线、改变它的输出延迟
（把 `<audio>` 用 MediaElementAudioSourceNode 接进 WebAudio 也试过，Chromium 在 seek 之后
有速率怪癖会把音乐放快）。

现在改成 **WebAudio 直接播解码好的 AudioBuffer**：

- seek = 用新的 `BufferSource` 从指定 offset 起播，采样级精确、没有管线重建
- 音乐和打点音挂在**同一条输出总线**上 → 画面 / 打点音 / 音乐三者同一个时钟、同一个输出延迟
- 画面再往前扣一个 `audioCtx.outputLatency`，对齐的是你**耳朵里听到**的那一刻
- 解码失败（个别坏文件）自动回落到 `<audio>` 直出；想强制用 `<audio>` 加 `?media=1`
- 排查用 `?debug=1`：左下角显示 `chart` / `audio` / 后端 / 输出峰值，`out=0` 即说明没声音送出去

实测：播放速率 seek 前后都是 1.000×，键盘快进 5 秒精确落在目标位置，暂停/继续精确衔接，
切歌自动重新解码。

## 打点音

- 拍手、太鼓「咚 / 咔」重写得更实（加了谐波和击打瞬态，笔记本喇叭也听得清）
- 喵改成两个共振峰 + 颤音的合成音，更像人声
- **排程与渲染解耦**：提前 120ms 用 WebAudio 时间轴排好，掉帧也不会跑偏、不会一帧内挤一堆音
- 音量上限 100% → **200%**
- 可选真素材：根目录 `se/{clap,nyan,don,ka}.{ogg,mp3,wav,m4a,flac}`，有就用真素材、没有回落合成音

## 同押光晕

- 同一时刻一起按的 marker，数字带霓虹光晕 + 两圈外扩波纹，整批同步呼吸
- 光晕严格裁在 marker 格子内，不会溢到相邻格
- 「同押光晕」可开关，颜色可用取色器换

## 其他

- 拖动进度条改成「拖动只预览、松手才 seek 一次」（避免几十次/秒地打断音频）
- 曲尾空白截断：时长 = 最后一个 note + 1.2s（与音源长度取小）
- 时钟不再外推过头：只在确实推进时补，且最多补 55ms，跳转后先禁用

## 整合包 / 部署

- **Linux 服务器（带曲库，解压即用）**：`python3 tools/build_php_package.py` 产出
  约 2.6 GB 的整包，丢到宝塔站点根目录解压即可（包内 `README.txt` + `start.sh`）
- Release 附件是**不带曲库**的桌面版：解压直接运行，首次启动用菜单
  「文件 → 选择站点目录（site/）」指向自己构建的 `site/`（会记住）
