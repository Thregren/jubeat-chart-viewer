这一版全是手机上踩到的坑 + 两处观感：**切后台回来没声音**、**iOS 静音提示**、
**搜索忽略符号**，以及**物量条重做成官方那种小方块栅格**。

## 一、手机切后台再回来没声音（必须刷新）

WebAudio 的 `BufferSource` 被系统掐掉之后，光 `resume()` 是救不回来的 —— 源已经没了，
画面照走却没声音，以前只能刷新页面。现在：

- 进后台时记下播放位置，回到前台等 `AudioContext` 真的回到 `running`，
  再按那个位置**重起一个源**接上
- `resume()` 在 iOS 上是异步的，还可能先 resolve 而状态仍停在 `interrupted`，
  所以是「resume + 每 120ms 轮询状态」一起上，最多等约 1.5 秒；等不到也照办，
  不能因为等它把播放卡死
- **桌面端不吃这套**：切标签页时 `AudioContext` 一般还是 `running`，这条路直接返回，
  不重建源 —— 否则每切一次标签页都听得到一次断音
- 触摸 / 按键上再挂一层兜底：任何一次手势发现 `AudioContext` 不在 `running` 就顺手走一遍
  （iOS 上 `resume()` 只有在手势里调才一定成功）

## 二、iOS / iPadOS 提示关掉系统静音

静音拨片一拨，WebAudio 和 `<audio>` 一起哑，而页面**没有任何 API 能读到这个状态**，
只能主动提示一次：进页面 0.9 秒后浮出一条 7 秒的提示
「检测到 iOS / iPadOS：请关掉系统静音（侧边拨片），否则可能没有声音」，然后自动消失
（不是需要点掉的弹窗）。

iPadOS 13 起 `navigator.platform` 是 `MacIntel`，所以除了 UA 里的
`iPad/iPhone/iPod`，还要靠 `maxTouchPoints > 1` 一起认。

## 三、长押筛选文案

`只要长押（含 HOLD）` → **`只要长押`**（括号里的 HOLD 是废话）。

## 四、搜索忽略符号

关键词和曲名 / 作曲 / 机台名都先做 **NFKC（全角→半角、合成字符拆开）+ 小写 +
去掉所有空白 / 标点 / 符号**，所以：

- 输入 `SCU` 能搜到 `S-C-U`（实测 31 首，包含 `Triple Journey -S-C-U EDITION-`）
- 输入 `jubeat plus` 能搜到 `jubeat+`
- 先按原样匹配一遍，没命中才走归一化这条 —— 免得把本来能精确命中的结果也拉进来
- 关键词全是符号（归一化后为空）时直接跳过归一化那次比较

## 五、物量条：官方那种小方块栅格

控制条上方那条物量显示改成了官方结算画面那张分布图的画法（**高度一点没动**，
仍然是桌面 36 px / 窄屏 46 px / 特别矮的屏 32 px）：

- **一格一格的小正方形**：5 px 一格（4 px 亮面 + 1 px 暗缝），暗金边 + 金芯，
  缩到 36 px 高也看得出是「小方块」而不是小圆点
- 方块必须是正方形，所以横着一格多宽只能由**条子高度**反推：桌面码 4 层、窄屏码 6 层。
  想把方块做大就得多减层数，这里选了「层数少一点、方块保真」这条
- 柱高按这一段（约 0.5 秒）的 note 数线性映射到层数，**有 note 就至少亮一格**，
  所以底部永远有一条连贯的基线，上面是高低起伏 —— 这才是官方那张图的样子
- **长押覆盖的整列填满**（那段时间手指一直按着）；颜色和普通列**完全相同**，
  只靠「整列到底」来认
- 每 30 秒一条淡竖线，条子 ≥ 40 px 高才写刻度（矮条子上字会糊住方块）
- 悬停提示改成报「前后各 1 秒」的 note 数：柱子本身不到 1 秒宽，
  再按「某一格」报数既看不清也没意义

```

铺面查看器/player/static/*.js           →  <站点根>/static/     （九个 app-*.js + core/sfx/record）

铺面查看器/player/static/record.css     →  <站点根>/static/record.css
```
