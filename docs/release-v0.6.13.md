## 一、问题：为什么「没用过的 marker」会缺前半段

marker 贴图是**网络资源**，动画却是**按谱面时钟逐帧画的**，这两件事速度对不上就会缺帧：

```
拍点前 517 ms   ←── MA 通道 16 帧接近动画（每帧 33.3 ms） ──→   拍点   命中爆发 H4
```

以前的逻辑是「选完立刻切过去」，而一套没缓存过的设计要现拉 40 张 PNG。于是切过去的一瞬间，
开头的 MA 帧还在路上：近处那几帧旧版会退到 ±4 帧（≈133 ms）以内顶住，再远就直接整格空着 ——
用户看到的就是「这套 marker 缺前半段」。

冷缓存 + 限速（300 KB/s、120 ms 延迟）下的实测，**切换那一刻**同一格在 6 个时间点的画布像素数：

| 时刻（相对命中） | 修复前 | 修复后 |
|---|---|---|
| −0.45 s | 0 像素（空格） | 26326 像素 |
| −0.25 s | 0 像素（空格） | 24739 像素 |
| −0.05 s | 0 像素（空格） | 26394 像素 |
| ±0.00 s | 0 像素（空格） | 21500 像素 |
| +0.10 s | 0 像素（空格） | 21500 像素 |
| +0.30 s | 0 像素（空格） | 21500 像素 |

## 二、切设计之前，先等「肉眼会缺的那部分」到齐

按「缺了会不会一眼看出来」把一套素材分成两组：

| 分组 | 内容 | 处理 |
|---|---|---|
| 门槛 | `MA` 接近动画 24 帧 + 面板边框 `FR` | **到齐才真正切过去**（一套约 0.5 MB） |
| 后台 | 命中爆发 `H4` 16 帧 | 不挡切换，跟着后台补齐 |

用户点完下拉不会「没反应」：素材没到齐时下拉旁边显示「素材载入中…」，上一套设计继续正常播；
到齐（或 12 秒安全网到点）再换。连着换两次只有最后一次生效 —— 先选的那套加载慢，不会把后选的
顶掉。**已经缓存过的设计走快路径，立刻切**，所以日常换回来换回去感觉不到这个门槛。

## 三、退帧：宁可慢半拍，也不开天窗

真到画的时候某一帧还没就绪，就退到**同一通道里最近的一帧**；连一帧都没有时，命中爆发
（`H` 通道）再退到同设计 `MA` 里「拍点上」的那一帧 —— 官方规格里 MA 的第 15 帧画的就是命中
瞬间的姿势，比空格好得多。实测上表里 +0.00 s 之后那三格就是这么顶住的。

顺带补了**失败退避重试**：线上贴图是按 IP 限流的，一次 429 会让那张图**永久**坏掉（浏览器不会
自己再试），而 429 响应还带着 30 天的 `Cache-Control`。现在每张图最多重试 3 次
（0.4 s / 1.2 s / 3 s），重试请求换一个查询串绕开缓存里的错误响应；贴图一到就补画一帧，
暂停时也能看到它出现。

## 四、预载只拉真正会画的帧

查看器是「按谱面全 PERFECT 播放」，所以命中爆发永远只用第 4 档。以前预载会把 4 档 `H`
全拉进来，其中 3 档**永远不会被画出来**，白拉一半字节。现在只拉 `MA` 全程 + `H4` + `FR`：
首次使用一套设计的下载量从约 1.8 MB 减到约 0.9 MB，冷启动那段空窗也就短了一半。
