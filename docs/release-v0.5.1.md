这一版只有两件事：修掉 v0.5.0 里长押曲目会多出一堆「不存在的 note」的问题，
以及让前端在浏览器捧着旧页面时能自己刷新。桌面端 / 服务器端的跑法没变。

## 修：长押曲目渲染出大量不存在的 note

`.mc` 里长押除了 `beat` / `index`（起点），还写了 `endbeat` / `endindex`。
之前把 `endindex` 当成了「长押另一头的键」，于是**每个长押都会在多出来的那一格上亮一个键**。

- 那个字段的真身是 jubeatools 里的 `tail_tip`：**长押尾巴朝哪个方向收尾**，是方向指示，
  不是第二个 pad，更不是第二条 note
- 实测这个偏移量在 1–3 格之间随机、和长押时长完全无关（1 拍的可能偏 2 格，12 拍的也可能偏 2 格）；
  抽查 60 个长押，那个位置上没有任何 note
- 「飽和世界」EXT（60 个长押）整首 435 个采样点里有 **434 个**存在幻影格子——比如 3.5 秒时
  pad 12 和 pad 14 同时亮着，但谱面里只有 pad 12 有 note
- 修完复验：「飽和世界」EXT 与「pray nightly」EXT 都是 **0 幻影**

现在一个长押 = 一个键按住 + 倒计时。`endindex` 仍然解析出来放在 `note.tailTip` 上（附注释），
主要是留个记录，防止以后又把它当 note 点亮。

> 顺带说明：试过把 `tail_tip` 画成方向箭头（先是「接近时滑进位、按住时往外推」的移动版，
> 后来改成静止版），实际看着都太乱——长押那一格本来就有扇形填充 + 倒计时。
> 两个版本都撤掉了，现在那一格没有任何多余图形。

## 新：前端版本自检

nginx 给 js/css 挂了 12h 缓存，靠 `index.html` 里的 `?v=` 换新。但如果浏览器手里还捧着一份
**旧的 index.html**（iOS 的缓存、后台标签页从内存恢复、bfcache 都会这样），它就只会去拿旧的
`?v=…` 那份 js —— 表现就是「明明上线了，页面上还是老样子」，只能自己清缓存。

现在播放器会：

- 启动时、切回前台时、以及每 5 分钟，用 `no-store` 拉一次 `index.html`，比对里面的 `?v=`
- 版本不一致就 console 提示并自动重载一次（每页只重载一次，不会来回刷）
- 本地开发（没有 `?v=`）不参与

## 部署 / 更新

Release 附件是**不带曲库**的桌面版（每个约 100 MB）：解压直接运行，首次启动用菜单
「文件 → 选择站点目录（site/）」指向自己构建的 `site/`（会记住）。

服务器上更新前端只要传这三个文件，曲库一个字都不用重传：

```
铺面查看器/player/static/index.html   →  <站点根>/index.html
铺面查看器/player/static/app.js       →  <站点根>/static/app.js
铺面查看器/player/static/style.css    →  <站点根>/static/style.css
```

**记得同时改 `index.html` 里的 `?v=`**（只要和之前用过的都不同就行，不必等于 app 版本号），
否则浏览器会继续用缓存里的旧 app.js。
